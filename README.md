# 野生動物ハンティングライフ

スマートフォン（横画面）向けの、3D狩猟ゲームです。インストール不要で、ブラウザだけで遊べます。
拠点で準備 → フィールド探索 → 動物・痕跡の発見 → 銃猟／罠 → 売却・報酬 → 成長、という流れを繰り返します。

---

## 1. ファイル構成

| ファイル | 内容 |
|---|---|
| `index.html` | 画面の骨組み（ここを開くとゲームが始まります） |
| `style.css` | 見た目（ボタン配置・色・横画面/小さい画面への対応） |
| `data.js` | **ゲームの数値・定義**（動物、エリア、銃、装備、罠、ミッション、報酬、バランス値） |
| `game.js` | ゲーム本体（セーブ、3D表示、操作、動物の行動、狩猟、罠、ミッション、各画面） |
| `tests/` | 自動テスト一式（Node.jsがあれば `sh tests/run_all.sh` で実行） |

> 動物を増やす・金額を変える・ミッションを足す、といった調整は、基本的に `data.js` だけを編集すれば行えます。

## 2. GitHubで公開する手順（プログラミング不要）

1. https://github.com でアカウントを作成してログインします。
2. 右上の「＋」→「New repository」を選びます。
   - Repository name：`hunting-life`（好きな英数字でOK）
   - 「Public」を選び、「Create repository」を押します。
3. 作成された画面の「uploading an existing file」をクリックします。
4. この**フォルダの中身**（`index.html` `style.css` `data.js` `game.js` `README.md`、`tests` フォルダ）をまとめてドラッグ＆ドロップします。
   - **フォルダごとではなく、中のファイルを**入れてください（`index.html` が一番上の階層に来る必要があります）。
5. 下の「Commit changes」を押します。
6. 「Settings」→ 左メニュー「Pages」を開きます。
   - 「Source」を「Deploy from a branch」にします。
   - 「Branch」を `main`、フォルダを `/ (root)` にして「Save」を押します。
7. 1〜2分待つと、同じ画面に公開URLが出ます。
   `https://（あなたのユーザー名）.github.io/hunting-life/`
   スマートフォンでこのURLを開けば遊べます。

**更新するとき：** 変更したファイルを、同じ手順4〜5でもう一度アップロード（上書き）します。

### 注意
- **セーブデータは、そのURLのブラウザの中に保存されます。** URLやリポジトリ名を変えると、以前のセーブは引き継がれません。ブラウザの「サイトデータ削除」でも消えます。
- 3D表示のために、外部の `three.js`（cdnjs）を読み込みます。**通信できない状態では起動できません**（その場合は案内が表示され、セーブは消えません）。完全にオフラインで使いたい場合は、`three.min.js`（バージョン r128）をダウンロードして同じ場所に置き、`index.html` の該当行の `src` をそのファイル名に変えてください。

## 3. 遊び方

- 画面は**横向き**で遊びます（縦のときは回転を促す表示が出ます）。
- **左側ドラッグ：移動 ／ 右側ドラッグ：視点**
- 「通常移動／慎重移動」：慎重にすると動物に気づかれにくくなります。
- 「構える」で照準が出ます。**「射撃」ボタンを押したときだけ**撃ちます。歩いているときや構えた直後は弾がばらつきます。
- 痕跡・物音は動物のヒントです。近づくと「痕跡を調べる」が出ます。
- 「罠」ボタンで罠を設置します。**現実の時間**で最大48時間かけて捕獲判定が進みます（アプリを閉じていても進みます）。
- 拠点では、施設に近づくか、メニューから各画面を開けます。獲物は「所持品・売却所」で売却・資源化します。
- 操作説明は初回に表示され、メニューの「操作説明」からいつでも見られます。

## 4. セーブ・ロードの仕組み

- 保存先：ブラウザの `localStorage`（外部サーバーには何も送りません）。
- 自動保存のタイミング：画面（エリア）の移動、捕獲・売却・購入・報酬受け取りなどの重要な操作、アプリを閉じる／別のタブへ移るとき。
- **安全な書き込み**：一時領域に書く → 内容を検証 → 本体に書く、の順で行い、直前の世代を**バックアップ**として残します。保存に失敗しても、既存のデータは上書きされません（失敗時は画面に通知）。
- **読み込み時の修復**：本体が壊れていればバックアップから復元します。値が不正・不足している項目は、有効な部分を残したまま初期値で補います。
- **罠の経過時間**：設置時刻と判定回数から再計算します。判定結果は罠ごとの乱数の種で決まるため、再起動や再読み込みで結果が変わることはありません。

## 5. Firebase等について

**現在のバージョンはFirebaseを使っていません。**単体で完結しており、設定は不要です。
次の機能を追加したい場合に、Firebaseなどのサーバー側の仕組みが必要になります（未実装）。

| 追加したい機能 | 必要なもの |
|---|---|
| 端末をまたぐセーブの引き継ぎ | Firebase Authentication（匿名ログインなど）＋ Firestore |
| **アプリを完全に閉じている間の通知**（罠に獲物がかかった等） | Firebase Cloud Messaging ＋ Service Worker ＋ 通知を送るサーバー側処理 |

導入する場合の基本方針（概要）：Firebaseでプロジェクトを作成 → Authenticationで匿名ログインを有効化 → Firestoreのセキュリティルールを「ログインした本人のデータだけ読み書き可」に設定。**ルールを開放したままにしないでください**（他人がデータを書き換えられます）。この部分は未実装・未検証です。

| 画面配置（8種類の画面サイズ×通常/構え中） | 16パターン | 重なり・はみ出し 0件 |

**開発中に見つかって修正した不具合（主なもの）**
- 読み込み時に「初期値の見本」が上書きされ、壊れた値を修復できない／犬のデータ破損で全進行が初期化される。
- 小さい横画面で「構える」ボタンがミニマップ・銃切替ボタンに重なる。
- ノッチ付き端末で操作ボタンが切り欠きに隠れる可能性。
- 中断された作業で動物の生成処理が壊れていた。

**探索バランスの測定**（理想的に歩き回る動きのシミュレーション。実際の人は約2倍かかる想定）

| エリア | 最初の手がかり(中央値) | 最初の動物発見(中央値) |
|---|---|---|
| 里山 | 約71秒 | 約35秒 |
| 森林 | 約54秒 | 約131秒 |
| 山間部 | 約110秒 | 約75秒 |

仕様の目安は、手がかり1〜3分／動物2〜5分です。手がかりは目安内。里山は動物がやや早く見つかる傾向があり、実機で遊んだ感触で調整してください（`data.js` の `sight.base`、各エリアの `max`、`spawnMin`）。

## 8. 未確認事項・未解決の問題・今後の拡張

**実機確認が必要（この開発環境にはブラウザ・スマートフォンがなく、実画面での確認ができませんでした）**
- 実際のスマートフォンでの表示、タッチ操作の手応え、描画の軽さ
- 夜・雨・霧の見た目、画面回転・アドレスバーの出入り
- ゲームバランス全般（捕獲率、金額、探索の長さ）。数値は初期値です

**既知の制約**
- アプリを閉じている間の端末通知は不可（Firebase等のサーバー側の仕組みが必要）。
- 端末の時計を進めると罠の時間も進められます（サーバーなしでは防げません）。
- 外部の three.js を読み込むため、初回は通信が必要です。

**拡張候補**
- 閉じている間の通知、クラウドセーブ（Firebase）
- 音（BGM・効果音）、動物・エリア・犬種の追加、地形の起伏
- ツキノワグマなど特殊な動物の行動
