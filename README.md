# 野生動物ハンティングライフ

スマートフォン（横画面）向けの、3D狩猟ゲームです。インストール不要で、ブラウザだけで遊べます。
拠点で準備 → フィールド探索 → 動物・痕跡の発見 → 銃猟／罠 → 売却・報酬 → 成長、という流れを繰り返します。

---

## 1. ファイル構成

| ファイル | 内容 |
|---|---|
| `index.html` | 画面の骨組み（ここを開くとゲームが始まります） |
| `style.css` | 見た目（HUD・ボタン・各画面のデザイン、縦持ち回転時の安全領域対応） |
| `data.js` | **ゲームの数値・定義**（動物、エリア、銃、装備、罠、ミッション、報酬、バランス値） |
| `terrain.js` | **地形層**（高さ・区域・小川/林道/田畑・歩行可否・斜面の速度・視線・障害物の空間グリッド）。描画やゲーム状態に依存しない純粋な関数 |
| `models.js` | **3Dモデル層**（GLBの読み込み、アニメーションの状態管理、読み込み失敗時の関節付き代替モデル）。ゲーム本体とは `ModelKit.create(種類)` だけでつながる |
| `assets/models/` | 3D素材(GLB)の置き場所。置くだけで自動で使われます（手順は中のREADME） |
| `tools/inspect_glb.js` | 素材の点検ツール（ポリゴン数・アニメーション・テクスチャ寸法・容量をスマホ向け予算と照合） |
| `ui.js` | **画面まわり**（縦横の回転、通知、メニュー・各画面の描画、HUD、射撃の閃光/音/振動） |
| `game.js` | ゲーム本体（セーブ、3D表示、操作入力、動物の行動、狩猟、罠、ミッションの処理） |
| `manifest.webmanifest` `icon.svg` | ホーム画面に追加したときの設定（Androidでは横固定・全画面） |
| `tests/` | 自動テスト一式（Node.jsがあれば `sh tests/run_all.sh` で実行） |

> 動物を増やす・金額を変える・ミッションを足す、といった調整は、基本的に `data.js` だけを編集すれば行えます。

## 2. GitHubで公開する手順（プログラミング不要）

1. https://github.com でアカウントを作成してログインします。
2. 右上の「＋」→「New repository」を選びます。
   - Repository name：`hunting-life`（好きな英数字でOK）
   - 「Public」を選び、「Create repository」を押します。
3. 作成された画面の「uploading an existing file」をクリックします。
4. この**フォルダの中身**（`index.html` `style.css` `data.js` `terrain.js` `models.js` `ui.js` `game.js` `manifest.webmanifest` `icon.svg` `README.md`、`assets` `tools` `tests` フォルダ）をまとめてドラッグ＆ドロップします。
   - **フォルダごとではなく、中のファイルを**入れてください（`index.html` が一番上の階層に来る必要があります）。
5. 下の「Commit changes」を押します。
6. 「Settings」→ 左メニュー「Pages」を開きます。
   - 「Source」を「Deploy from a branch」にします。
   - 「Branch」を `main`、フォルダを `/ (root)` にして「Save」を押します。
7. 1〜2分待つと、同じ画面に公開URLが出ます。
   `https://（あなたのユーザー名）.github.io/hunting-life/`
   スマートフォンでこのURLを開けば遊べます。

**更新するとき：** 変更したファイルを、同じ手順4〜5でもう一度アップロード（上書き）します。

### 注意
- **セーブデータは、そのURLのブラウザの中に保存されます。** URLやリポジトリ名を変えると、以前のセーブは引き継がれません。ブラウザの「サイトデータ削除」でも消えます。
- 3D表示のために、外部の `three.js`（cdnjs）を読み込みます。**通信できない状態では起動できません**（その場合は案内が表示され、セーブは消えません）。完全にオフラインで使いたい場合は、`three.min.js`（バージョン r128）をダウンロードして同じ場所に置き、`index.html` の該当行の `src` をそのファイル名に変えてください。

## 2.5 3Dモデル（第2次改修 Phase B）

- プレイヤー・動物6種・猟犬は、`models.js` を通して表示されます。**素材(GLB)が `assets/models/` にあればそれを使い、無い・読み込めない場合は関節付きの代替モデルで自動的に動きます**（ゲームは止まりません）。
- 代替モデルも、待機・歩行・走行・警戒・逃走・構えで姿勢が変わり、実際の移動速度に歩幅が連動します（動物ごとに体格・歩き方が違います）。
- **現在、外部素材は未導入です**（すべて代替表示）。素材の調達方針は別途ご相談中です。導入手順は `assets/models/README.md` を参照してください。
- 素材を使う場合は、`data.js` の `credit` に作者・ライセンス・URLを記入します（設定 → クレジット に自動表示され、記入漏れはテストで検出されます）。

## 2.6 地形（第2次改修 Phase C・前半）

- 各エリアは**高低差のある地形**になりました（`terrain.js`、設計は `data.js` の `DATA.terrain`）。里山・森林・山間部・奥山で起伏の強さが違います。
- 区域：**林道**（平らで歩きやすい）／**田畑**（開けた平地）／**雑木林**（木が密）／**小川**（谷＋水面。水の中は歩けるが遅い）／開けた場所。木・岩は区域ごとの密度で配置され、林道・水中には生えません。
- 急な斜面は歩けず、上りは遅く下りは速くなります。障害物にぶつかると、壁に沿って滑るように進みます。
- 動物は種類ごとに好む区域に出ます（シカは開けた場所、イノシシは雑木林など）。出発地点から歩いて行けない場所には出ません。
- 視線は丘に遮られます。高い所から見下ろすと見通しが少し良くなります。射撃も、丘越しには当たりません。
- エリアの端は丘になり、見えない壁ではなく地形で行き止まりになります。
- 設置済みの罠が新しい地形で水・急斜面・木に重なる場合は、最も近い使える場所へ自動で移ります。
- 同じエリアは毎回同じ地形・同じ木と岩の配置です（罠や痕跡の位置関係が変わりません）。
- **動物の行動（警戒・逃走・イノシシの威嚇と突進・クマ・群れ・追跡）の作り直しは Phase C の後半**で行います（現在は従来の行動のままです）。

## 3. 遊び方

- **画面の向き**：縦持ちでも、回転ロックを解除した横持ちでも、**ゲーム画面は常に同じ横向きの画面**で遊べます。
  - 縦のまま端末を開いた場合は、ゲーム画面を自動で90度回して横表示にします。端末を横に持って遊んでください。
  - 回転の向きが逆に見える場合は、画面左下の「↻向き」ボタン、または「設定」から反転してください。
  - Androidでは、「はじめる」を押したときに全画面＋横固定を試みます（端末・ブラウザによっては働かない場合があります）。
  - iPhoneのSafariは向きの固定ができないため、回転表示で対応します。
- **左側ドラッグ：移動 ／ 右側ドラッグ：視点**
- **歩きながらでも、構える🎯・慎重移動🚶・銃の切替・調べる、を押せます**（ボタンは「押した瞬間」に反応します）。
- 「構える」で照準が出ます。**「撃つ」ボタンを押したときだけ**発砲します。発砲すると、画面の閃光・銃の反動・発砲音・振動（対応端末）が出て、命中／仕留めた／外れの表示が出ます。撃つボタンの外周はクールダウンを示します。
- 痕跡・物音は動物のヒントです。近づくと「痕跡を調べる」が出ます。
- 「罠」ボタンで罠を設置します。**現実の時間**で最大48時間かけて捕獲判定が進みます（アプリを閉じていても進みます）。
- 拠点では、施設に近づくか、☰メニューの一覧から各画面を開けます。獲物は「所持品・売却」で売却・資源化します。
- 通知は画面中央を避け、上端のHUDの間に小さく表示します。捕獲結果などの重要なものだけ少し大きく出ます。
- 操作説明は初回に表示され、メニューからいつでも見られます。

## 4. セーブ・ロードの仕組み

- 保存先：ブラウザの `localStorage`（外部サーバーには何も送りません）。
- 自動保存のタイミング：画面（エリア）の移動、捕獲・売却・購入・報酬受け取りなどの重要な操作、アプリを閉じる／別のタブへ移るとき。
- **安全な書き込み**：一時領域に書く → 内容を検証 → 本体に書く、の順で行い、直前の世代を**バックアップ**として残します。保存に失敗しても、既存のデータは上書きされません（失敗時は画面に通知）。
- **読み込み時の修復**：本体が壊れていればバックアップから復元します。値が不正・不足している項目は、有効な部分を残したまま初期値で補います。
- **罠の経過時間**：設置時刻と判定回数から再計算します。判定結果は罠ごとの乱数の種で決まるため、再起動や再読み込みで結果が変わることはありません。

## 5. Firebase等について

**現在のバージョンはFirebaseを使っていません。**単体で完結しており、設定は不要です。
次の機能を追加したい場合に、Firebaseなどのサーバー側の仕組みが必要になります（未実装）。

| 追加したい機能 | 必要なもの |
|---|---|
| 端末をまたぐセーブの引き継ぎ | Firebase Authentication（匿名ログインなど）＋ Firestore |
| **アプリを完全に閉じている間の通知**（罠に獲物がかかった等） | Firebase Cloud Messaging ＋ Service Worker ＋ 通知を送るサーバー側処理 |

導入する場合の基本方針（概要）：Firebaseでプロジェクトを作成 → Authenticationで匿名ログインを有効化 → Firestoreのセキュリティルールを「ログインした本人のデータだけ読み書き可」に設定。**ルールを開放したままにしないでください**（他人がデータを書き換えられます）。この部分は未実装・未検証です。
